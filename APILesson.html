Lesson 2 — APIs: from using AI to building with it

Advanced~30 minDual track: no-code + code

Jargon, in plain words

New techy words for this lesson, explained like you're 12 — with when and why you'd use them.
API (Application Programming Interface)
A way for two pieces of software to talk to each other and swap information. Like a waiter: you give your order, they carry it to the kitchen, and bring the food back. When: when you want a program (not a person typing) to send text to the AI and get an answer back. Why: it lets you build AI into your own apps and automations.
Request & response
The message you send is the request; what comes back is the response. Your order is the request; the meal is the response.
API key
A secret password that says "this is me" and lets you use the API (it's also what you're billed on). Like your personal membership card — never let anyone else have it. Why: security and billing. When: on every request.
Token
The little chunks of text an AI reads and writes — you pay per token. Like counting the letters in an old pay-per-character text message. Why: cost and length are measured in tokens.
Structured output (JSON)
Getting the answer back in a tidy, labelled format a program can read — not just a paragraph. Like a neatly filled-in form instead of a handwritten note. When: when other software needs to use the answer automatically. Why: it's reliable and machine-readable.
Rate limit
A cap on how many requests you can send in a period of time. Like a fairground ride that only lets so many people on each minute. Why: keeps the service fair and stable for everyone.
What you'll be able to do: explain what an API is in plain terms, and send text to an AI to get a tidy structured (JSON) answer back — the step that turns you from someone who uses AI into someone who can build with it.
The scenario: An online shop gets 2,000 customer messages a day — no human can read them all. With an API, a small program sends each message to the AI and gets back a tidy label like {"sentiment":"angry","topic":"delivery"} that drops straight into their system. That's an API turning a mountain of text into organised data.

1What an API really is

When you chat in an app, you are the one typing. An API lets a program do the talking instead: it sends a request (your text + instructions) and gets a response (the AI's answer). Every request carries your secret API key. If you ask for structured output, the answer comes back as tidy JSON a computer can slot straight into a spreadsheet, a database or an app.

When it's used: classifying thousands of reviews, auto-drafting replies, tagging data, powering a feature inside your own software. Why it's used: it works at scale, automatically, without a human copy-pasting each item.

2Try it — no code

You can experience an API request in a free playground (a web page where you send a request and see the response) — no programming needed.

Try it · Google AI Studio (free)
  1. Open Google AI Studio and sign in.
  2. In the prompt box, ask for a structured answer, e.g.:
    "Classify this review. Reply ONLY as JSON with keys sentiment and topic. Review: 'My parcel arrived late and damaged.'"
  3. Run it. You'll get back tidy JSON like {"sentiment":"negative","topic":"delivery"}.
  4. See the "Get code" button? That's the exact request a program would send — you just did it by hand.

3Go deeper — with code (optional)

Skip this if you like — you've already sent a request above. For developer-minded learners, here's the same idea in a few lines. Read it like a recipe.

Go deeper · a minimal API call 
# 1) Keep your key SECRET - load it from the environment, never write it in the code you share
import os
from openai import OpenAI          # install the provider's SDK first
client = OpenAI(api_key=os.environ["OPENAI_API_KEY"])

# 2) Send a request, asking for a STRUCTURED (JSON) answer
reply = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user",
      "content": "Classify this review. Reply ONLY as JSON with keys sentiment and topic. "
                 "Review: 'My parcel arrived late and damaged.'"}]
)

# 3) Read the structured response
print(reply.choices[0].message.content)   # -> {"sentiment": "negative", "topic": "delivery"}

SDK = a ready-made toolkit for your language so you don't build everything from scratch. Each provider's SDK differs slightly — always follow their official docs, and mind your rate limit and cost.

Guardrails — safety & ethics

  • Never expose your API key. Keep it out of public code, websites and screenshots — anyone who gets it can spend your money.
  • Set a spending cap in the provider's dashboard so a bug can't run up a huge bill.
  • Mind the data: don't send confidential or personal data; check the provider's data-retention and training settings.
  • Respect rate limits and handle errors, so your program fails safely instead of hammering the service.
Try this today (5 min): open a free playground and get the AI to reply only as JSON for a task of your choice. You've just made a structured API-style request.
Common mistake: putting your API key straight into code you share (or a public site). That's like posting your bank PIN. Keep it secret, use an environment variable, and rotate it if it ever leaks.
